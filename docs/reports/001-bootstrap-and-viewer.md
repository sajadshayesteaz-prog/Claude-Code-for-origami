**تاریخ:** ۲۷ مهر ۱۴۰۵ (۱۸ اکتبر ۲۰۲۶)
**مخزن کد:** Origami-App — commit `38d74a3` (شاخه `main`)
**اجراکننده:** Claude Code روی کامپیوتر کاربر (Windows 10)

## چه ساخته شد

- **اپ وب** (Vite 8 + React 19 + TypeScript) در پوشه `app/`. فایل `package.json` در ریشه مخزن است و Vite با `root: "app"` اجرا می‌شود.
- **نمایشگر الگو:**
  - باز کردن فایل `.fold` / `.svg` با دکمه انتخاب فایل، یا انتخاب از فهرست نمونه‌ها (۱۶ نمونه از `sources/samples/`). پیش‌فرض: `crane-sequence.fold`.
  - **نمای دوبعدی** با Rabbit Ear (`ear.convert.foldToSvg`). کوه: خط‌چین‌نقطه قرمز؛ دره: خط‌چین آبی؛ تای باز: خاکستری؛ لبه: سیاه. ضخامت خط مستقل از مقیاس الگو است.
  - **نمای سه‌بعدی** با Origami Simulator. نسخه‌ای سبک‌شده از آن در `app/public/origami-simulator/` داخل iframe اجرا می‌شود و از راه API پیام‌رسانی خودش (`importFold` / `importSVG`) کنترل می‌شود. یک فایل کوچک (`embed.js` و `embed.css`) منوهای شبیه‌ساز را پنهان می‌کند، میزان تا را پیش‌فرض ۱۰۰٪ می‌گذارد، پیام‌های `setFoldPercent` و `resetView` را اضافه می‌کند و هشدارها را به اپ برمی‌گرداند. Google Analytics حذف شده است.
  - هر frame از `file_frames` جداگانه به شبیه‌ساز فرستاده می‌شود (زاویه‌های `edges_foldAngle` همان frame). اگر frame زاویه نداشته باشد، از روی M/V ساخته می‌شود (±۱۸۰).
  - **پخش مرحله‌ای:** دکمه‌های قبلی/بعدی، شمارنده «مرحله n از N» (در فارسی با رقم فارسی)، و کلیدهای جهت‌نما. در فارسی ← یعنی مرحله بعد و → یعنی مرحله قبل. Home/End/PageUp/PageDown هم کار می‌کنند.
  - اسلایدر «میزان تا» (۰ تا ۱۰۰٪) و دکمه «بازنشانی دید» برای نمای سه‌بعدی.
- **فارسی/انگلیسی:** دکمه تغییر زبان در سرصفحه؛ فارسی با `dir="rtl"`. زبان انتخاب‌شده در localStorage می‌ماند.
- **مدل داده** در `data/schema/`:
  - `model.schema.json`: id، نام fa/en، دسته، دشواری ۱ تا ۵، طراح، کتاب + صفحه، شکل و اندازه کاغذ، تعداد مراحل، has3D و مسیر فایل FOLD، فهرست مراحل.
  - `step.schema.json`: شماره، مسیر تصویر (`steps/NNN.png|svg`)، متن fa/en، یادداشت، شماره frame در FOLD (اختیاری).
  - `progress.schema.json`: شناسه مدل، آخرین مرحله، زمان.
  - نمونه: `data/library/example-crane/` با `model.json` (۳۷ مرحله)، `crane.fold` و ۳۷ تصویر SVG مراحل که از frameها ساخته شده‌اند. نمونه Progress: `data/schema/examples/example-crane.progress.json`.
- **ابزارها** در `tools/`:
  - `validate-data.mjs` (`npm run validate:data`): همه `model.json`ها را با schema می‌سنجد و این‌ها را هم بررسی می‌کند: برابری id با نام پوشه، برابری `stepCount` با تعداد مراحل، ترتیب شماره‌ها، وجود فایل تصویرها و FOLD، و معتبر بودن `foldFrame`.
  - `sync-samples.mjs`: نمونه‌ها را از مخزن ارتباطی کپی می‌کند (`COMMS_DIR` از `.env`).
  - `sync-simulator.mjs`: Origami Simulator را از `vendor/` کپی و برای جاسازی آماده می‌کند.
  - `fold-frames-to-svg.mjs`: برای هر frame یک SVG الگوی چین می‌سازد.
- **`vendor/`:** هر ۱۲ مخزن با commit ثابت دریافت شدند و هیچ‌کدام تغییر محلی ندارند. دو بسته npm (`fold-0.12.0.tgz`، `rabbit-ear-0.9.41.tgz`) هم در `vendor/npm/` هستند.
- **Node.js:** روی کامپیوتر نصب نبود. با اجازه کاربر، نسخه پرتابل Node 22.23.3 در `%LOCALAPPDATA%\Programs\nodejs` باز شد (هش SHA-256 با فایل رسمی nodejs.org بررسی شد).

## چطور اجرا کنم

Node هنوز در PATH ویندوز نیست (پایین‌تر، بخش مشکلات). در Git Bash:

```bash
export PATH="$LOCALAPPDATA/Programs/nodejs:$PATH"
cd "/d/literature/کتاب/Origami/Origami-App"
npm install
npm run dev
```

سپس http://localhost:5173 را باز کنید.

دستورهای دیگر:

```bash
npm run validate:data      # اعتبارسنجی model.json
npm run build              # بررسی نوع‌ها و ساخت نسخه نهایی در dist/
bash "../Claude-Code-for-origami/sources/fetch-sources.sh" vendor   # دریافت منابع بیرونی
npm run sync:simulator     # کپی دوباره Origami Simulator از vendor/
npm run sync:samples       # کپی دوباره نمونه‌ها از مخزن ارتباطی
```

## تصمیم‌های فنی

1. **سه‌بعدی: اجرای خود Origami Simulator داخل iframe، نه بازنویسی حل‌کننده روی three.js.** حل‌کننده آن روی GPU و با shaderهایی است که داخل `index.html` تعریف شده‌اند، و همه کد به jQuery و متغیرهای global وابسته است. خوشبختانه شبیه‌ساز از قبل API پیام‌رسانی دارد (`importFold`، `importSVG` و پیام `ready`). بنابراین یک کامپوننت React (`Simulator3D.tsx`) آن را مثل یک ماژول با ورودی مشخص به کار می‌برد. برای فاز ۴ اگر ادغام عمیق‌تر لازم شد، می‌توان `dynamicSolver` را جدا کرد.
2. **دوبعدی: Rabbit Ear، نه FOLD viewer.** Rabbit Ear از قبل در پشته است، هم FOLD و هم SVG (`svgToFold`) را می‌خواند، برای هر نوع خط کلاس CSS می‌گذارد (`mountain`/`valley`/…)، و در فاز ۲ برای فلش‌های دیاگرام هم لازم می‌شود.
3. **نمونه‌ها و شبیه‌ساز در مخزن commit می‌شوند** (`app/public/samples/` حدود ۱۰۰ کیلوبایت، `app/public/origami-simulator/` حدود ۵.۴ مگابایت). دلیل: `vendor/` در git نیست ولی `npm install && npm run dev` باید روی یک clone تازه کار کند. برای به‌روزرسانی، `npm run sync:*` را اجرا کنید.
4. **ساختار:** `package.json` در ریشه مخزن و کد وب در `app/`. پوشه‌های `data/` و `tools/` کنار آن در ریشه می‌مانند.
5. **ورودی SVG** با قرارداد رنگ خود Origami Simulator مستقیم به آن داده می‌شود (`importSVG`)، و نمای دوبعدی آن را با `svgToFold` در Rabbit Ear می‌سازد.
6. **کلیدهای جهت‌نما به جهت خواندن بستگی دارند:** در فارسی ← یعنی مرحله بعد.
7. **i18n بدون کتابخانه:** یک فایل کوچک (`app/src/i18n.ts`) با رشته‌های fa/en و `Intl.NumberFormat` برای رقم‌ها.
8. **Node پرتابل** روی کامپیوتر کاربر (با تأیید کاربر).
9. **PWA** هنوز ساخته نشده است. برگه کار آن را صریحاً نخواسته بود و «بسته‌بندی موبایل» خارج از محدوده بود. پشته پیش‌فرض PWA را دارد؛ می‌شود در کار بعدی اضافه‌اش کرد.

## مشکلات و سؤال‌های باز

- **Node در PATH نیست.** ابزار ویندوز (winget) هم در دسترس نبود. برای اجرای ساده `npm` در هر ترمینال، یا مسیر `%LOCALAPPDATA%\Programs\nodejs` را به PATH کاربر اضافه کنید، یا نصاب رسمی Node LTS را نصب کنید. (این تغییر تنظیمات سیستم است و انجامش ندادم.)
- **محیط ایزوله (sandbox) Claude Code روی درایو D** گاهی نوشتن فایل‌های git را با خطا (`Invalid argument` و `fsync error`) قطع می‌کرد. برای دریافت `vendor/` و اجرای npm، دستورها بیرون از sandbox اجرا شدند. برای `git clone` و `commit` هم `core.fsync=none` لازم شد.
- **`fs.cpSync` در Node 22 روی مسیرهای فارسی ویندوز** بی‌صدا از کار می‌افتاد. ابزارها به‌جایش از یک تابع کپی ساده (`tools/fsutil.mjs`) استفاده می‌کنند.
- **هویت git** روی این کامپیوتر تنظیم نشده بود. commitها با همان نویسنده commitهای قبلی (`Claude <noreply@anthropic.com>`) و فقط برای همان دستور ساخته شدند؛ تنظیمات git کاربر تغییر نکرد.
- **`npm audit`:** دو آسیب‌پذیری (۱ متوسط، ۱ بالا) در `@xmldom/xmldom`، که بسته `fold@0.12.0` به آن وابسته است. این بسته هنوز در کد اپ استفاده نمی‌شود و برای `fold-convert` در فازهای بعد نگه داشته شده است. برای اپ شخصی و منتشرنشده خطر کمی دارد.
- در frameهایی که زاویه تای جزئی دارند، Rabbit Ear خط‌ها را با شفافیتی متناسب با زاویه می‌کشد. پس چین‌هایی که کمتر تا خورده‌اند کم‌رنگ‌ترند؛ این رفتار خود کتابخانه است.
- **سؤال برای claude.ai:** شبیه‌ساز هر frame را از حالت صاف شروع می‌کند و تا می‌زند؛ بین مرحله‌ها انیمیشن پیوسته وجود ندارد. آیا برای فاز ۴ انیمیشن بین دو frame لازم است؟
- منبع نمونه `example-crane` کتاب نیست، فایل آزمون Rabbit Ear است. فقط برای آزمودن schema است و باید با اولین مدل Komatsu جایگزین شود.

## پیشنهاد کار بعدی

1. افزودن Node به PATH (کاربر)، یا اضافه کردن یک `run-dev.bat` به مخزن.
2. **فاز ۲ — راهنمای تاهای پایه:** ساخت FOLD چندفریمی برای پایه‌ها با `bases.js` در Rabbit Ear، و یک صفحه آموزش روی همین نمایشگر (فهرست تاها و متن‌ها از claude.ai).
3. **پیش‌نیاز فاز ۳:** سنجش وضوح فایل اصلی کتاب Komatsu روی همین کامپیوتر. صفحه‌ای برای مرور یک مدل کتابخانه (خواندن `model.json` و نمایش `steps/` همگام با frame سه‌بعدی) هم می‌تواند از همین نمایشگر ساخته شود.
4. افزودن PWA (manifest و service worker) و ذخیره Progress در IndexedDB، اگر اولویت دارد.
